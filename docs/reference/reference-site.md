# Reference Site

[Documentation](../README.md)

Cooldown Gaming is the live Site the blueprint is tested against: a content
Site with an Astro Frontend and no ecommerce, generated by `gq new` and kept
in sync by `gq sync`. Use it whenever a check needs a real content Site
(readiness, publication events, delivery, smoke runs) instead of a throwaway
one.

| Part       | Address                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------- |
| Repository | [`Quick-Release/cooldowngaming`](https://github.com/Quick-Release/cooldowngaming) (private) |
| Frontend   | https://cooldowngaming.com                                                                  |
| CMS        | https://cms.cooldowngaming.com                                                              |
| Media      | https://media.cooldowngaming.com                                                            |

Its `gq.ops.json` names the project `cooldowngaming` with the `content`
variant.

## It's a playground

Downtime, resets and maintenance are expected there. A failed request means
"check its current state", not an incident: look at the Site before relying
on what it serves, and say what you found when a result depends on it.

## Where work goes

Tests and checks of the blueprint that use the Site live here. Changes to the
Site itself (its content, plugins, theme, deploys) belong in its own
repository and start a session there
([gq-platform ADR 0001](https://github.com/Quick-Release/gq-platform/blob/main/docs/adr/0001-ownership-of-work-across-getquick-repositories.md)).
